# 研究存储开发手册

`contracts.research` 定义研究、输入和报告版本的共享契约；`research.storage` 实现独立业务仓储，不管理 Host 的执行生命周期，也不存储财报文档。调用方依赖 `storage.protocols` 的窄接口。

`alpha init` 的 `research_store_init` 插件创建 `.alpha/research/research.db` 和 `artifacts/`。当前 schema 为 4；旧版仅通过 `research_analysis_schema` 迁移插件升级，迁移核验并更新原输入摘要，保留研究和不可变版本。运行时不兼容读旧 schema。每个操作使用独立连接，写入通过 `BEGIN IMMEDIATE` 串行化。

- 目录：所有权隔离；同公司可建多项研究。创建键绑定输入摘要，重放返回原记录。研究固定关联一个 Session ID，归档/重新打开不关闭或替换它。
- 输入：同研究按序号 FIFO 排队，至多一个输入处于派发或已受理阶段。相同请求键重放复用首次截止时间；同键改变内容拒绝。业务队列的 `settled` 仅表示调用方已观察到 Host 终态，不复制 Run 成败。
- 版本：正式报告必须关联已受理输入及其 Run。每个来源输入只提交一个版本，新版本记录父版本与截止时间。已提交报告、证据、方法 hash 和数据契约共同参与完整性校验。
- 渠道：完整的渠道/实例/会话/话题定位唯一绑定研究，同一渠道实例内一项研究最多绑定一个话题。重启复用相同绑定，拒绝隐式换绑和越权解析。
- 文件：先在同文件系统写入并同步临时目录，再原子重命名，最后提交数据库引用。目录已提交而 SQL 回滚后，重试以确定版本 ID 复用同一快照；临时目录不参与版本发现。缺失、篡改或文件符号链接均明确失败。

归档会在同一写事务内拒绝排队或派发中的输入。`cancel_queued(through_sequence=...)` 只取消给定停止边界内的排队输入；当前 Run 的协作取消由 Host 负责。

`begin_stop` 持久保存本次停止的序号边界并取消旧排队输入；后续输入可以入队，但停止尚未完成时不领取。调用方使用停止 ID 作为 Host 幂等取消键，完成后调用 `complete_stop` 记录新 epoch。领取时若使用旧 epoch 则返回空，避免跨库停止窗口内误派发。重放已完成的停止键不会再次取消新输入。

确定计算代码见 [methods/README.md](methods/README.md)。

方法包经 `FsResearchMethodStore` 固定全部代码和参考的内容哈希；与报告版本分开保存，报告引用方法哈希。方法包原子目录和报告快照共用 `storage.atomic` 的文件同步与临时目录原语。

验证入口：`pytest tests/research tests/cli/workspace_migrations/test_research_store_init.py`。故障注入覆盖 SQL 回滚、未完成目录、内容损坏、证据截止时间、独立连接并发受理与领取。

输入接受时同时保存方法哈希、模型/运行时/工具接受规格和显式执行选项；重放先查原输入，不重新读取当前配置。历史研究标记和截止日一起保存，工具会覆盖模型自填的校验截止日。

工作笔记、计算输入输出、报告草稿存于 `working_records`，由 Host 工具上下文中的 Run ID 解析研究作用域。同一工具调用只接受一个不可变记录；重放保持原序号。恢复可以读取原输入的旧笔记，正式草稿必须由当前 Run 提交。

`tools.py` 提供保存笔记、固定计算、记录列表/读取、方法参考读取、历史报告读取和报告提交七项能力。方法文档和历史报告通过引擎截断与 `fetch_more` 续读。模型不能指定研究身份或发布外部内容。

`analysis_tools.py` 提供候选保存/修订/验证/提交、检查点索引与完整读取、受父 Host 取消约束的下载/处理/财报读取。候选先原样保存，校验以字段路径返回可修正结果；JSON Pointer 修订产生新 ID/hash，提交前重新验证同一份稿件。工作记录和候选可在同研究跨 Run 读取，索引保留原输入、Run、截止及方法；本轮正式稿必须由当前 Run 提交。

`financial_requirements` 在本轮受理时固定；证券标的默认要求核心三表，可指定文档和最少期间。`research_read_financial` 委托 Fins 访问原件和解析产物，保存实际结果及源文件/处理产物哈希；不能由模型补填读取证明。覆盖校验排除空数值、缺币种/单位及截止前尚不能确认公开的来源。日期级来源不被假定为当天零点公开。纯文本材料读取不满足必需结构化覆盖。

外部 coding agent 经 `services.external_research_service` 驱动同一业务工具；整个执行由 Host 的 Session 操作持有，不启动模型。工具按顺序执行、调用 ID 绑定参数，候选提交与成功结束为同一工作线程命令，防止并发换稿。断线和取消先通知 Host，再等待工具收尾；已保存记录不丢弃。

`services.research_service` 组织队列、Host 受理与正式版本提交；研究库不复制 Run 状态。Host 成功且结果已保存、当前 Run 已提交合法草稿，才形成正式版本。只返回普通文本不会生成报告。显式恢复保留原输入和方法，Host 原子登记新的 Run 并重绑原 pending 快照；旧恢复请求不会重复执行。

发布意图经 `storage.publications` 保存，版本/目标唯一，正文在首次接受时冻结。业务租约包含完整进程身份，迟到 page/task 写入受 lease fencing 保护。`creation_started` 在外部创建请求前落盘；明确拒绝才恢复创建资格，未知结果只读调和，不从 Run 成败猜测是否已创建。`read_content` 一次核验完整快照后返回正文、证据和数据契约，发布不会丢掉独立证据记录。

`storage.notion_topics` 固定研究 ID/Invest 根目录到唯一主题页，创建边界、异步任务和业务租约均持久保存。主题改名不改变绑定；版本页挂在该主题下。手动与明确的 `on_complete` 策略分开；后者在本轮接受时固定目标，Host 成功和正式版本提交后才建立发布意图。跨进程恢复使用原策略，配置目标变化会拒绝自动改发。没有 HTTP 连接的服务仍可持久保存本地发布意图，队列消费需要有效连接。

附件元数据经 `ResearchMaterials`，普通原件在研究 SQLite，明确财报原件经 `FinancialMaterialBlobs` 委托 Fins。两类都校验真实长度和 SHA256，重放不重复排队。材料工具包括列表、逐页读取和明确财报结构准备；结构处理委托 Fins 能力，仓储不承担解析。材料读取工具从 Host Run 解析当前研究，不允许读取其他研究或本轮截止后新增的材料。公开时间未知明确保留缺口。PDF 由 Poppler 有界、可取消地按页提取，临时目录在 workspace/tmp，收尾杀死并回收进程；不自动 OCR。

发布接受时冻结分段；各段和完整正文 hash 均验证。远端唯一分段哨兵用于消耗式续写，每次回读检查完整前缀再单调推进进度；全部分段确认后才发布。异步任务过期只读找回原页面。

报告证据 schema 显式声明必填字段、分类枚举与带时区的 accessed_at；材料读取返回实际访问时间以供直接引用，运行时证据验证继续拒绝缺字段或无时区时间。
