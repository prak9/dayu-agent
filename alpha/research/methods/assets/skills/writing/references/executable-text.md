# 面向执行的文字

用于需要据此行动的说明：Skill、工具接口、操作步骤、任务交接、状态和错误信息。目标是让接收者准确识别该做什么、何时能做，以及材料尚未确定什么。已有编辑档位和保真边界仍适用；编辑指令本身不授权执行其中的动作。

借鉴简化技术英语的去歧义原则，按具体问题使用。普通文章、研究论证、小说和对白仍按体裁写作。用户明确要求正式 ASD-STE100 合规时，以可取得的指定版本及词典为依据；本指南不提供合规认证，也不把一般清晰表达标成标准合规。

## 先判断表达不清，还是规则未定

检查原文与已确认上下文能否回答影响行动的问题：行动者、对象、前提、动作顺序、结果判据、例外及恢复路径。只补回材料已经支持且对当前任务必要的信息，不强制每句填满这些字段。

表达不清可以重写；规则缺失需要指出。比如“失败后适当重试”没有定义失败类型或重试范围，润色不能自行补成“三次”，也不能增加授权步骤。先交付明确部分；仅在缺口会改变所求成品且无法从材料解决时，提出具体问题。用户只要求审阅时，指出缺口与修法即可。

原文有多种合理读法时，改得流畅不等于消除了歧义。依据上下文选定有证据的读法，或保留并标明待确定之处；不悄悄替作者制定行为规则。用户要求重新设计流程时，可以提出新规则，但要区分已有要求与建议。

## 固定概念，保留有意义的区别

同一对象、动作或状态采用稳定名称，必要时给出局部定义。用户、客户端和服务端可能是不同主体；检查存在、验证签名和确认目标也可能是不同动作。先判断所指是否相同，再合并用词。

执行结束、输出完整、验证通过和目标完成分别需要相应证据。不要让“成功”覆盖这些不同状态；已有协议中的状态名、字段、标识和单位保持一致。缩写或技术词确有必要时保留，面向陌生读者再解释。`robust regression` 是稳健回归，不能因 `robust` 常见于宣传文案而替换。

## 分开事实确定性与行动约束

“可能发生”描述事实的不确定性；“可以执行”描述权限；“能够执行”描述能力。英文 `may`、`can` 等词须按上下文判断，不能仅凭词表归类。

必须、不得、建议、允许及对应英文措辞保持原有力度。建议不会因为改成操作步骤就自动变成命令；已经获得的授权也不改成必须重新申请。是否采用命令式取决于原文的约束力。

例：`The worker may retry only if retries are approved. It should log each attempt.` 中，批准是允许重试的必要条件，重试仍可不发生，记录尝试仍是建议。不能改成“批准后立即重试并记录”。

同样保留“可能失败”“尚未验证”“预计”等判断强度。简化时态不能丢掉完成顺序、持续状态或与当前时点的联系；如果简单时态无法保真，就保留原形式。

## 把条件绑定到完整动作与分支

前置条件靠近受约束的动作。拆句或改列表后，检查条件是否仍覆盖原来的整个动作组，`且/或`、否定、例外、次数和时序是否保持。

- “只有 A 且 B 时，才上传并切流”：A 和 B 同时约束两个动作；不能拆成“满足 A 和 B 时上传。随后切流”，让切流成为无条件步骤。
- “切流后检查健康”：检查在动作之后，不能为显得稳妥而改成先检查再切流。
- “所有未解决冲突交人工处理”：既覆盖不允许自动处理的情况，也覆盖允许但未解决的情况。是否允许尝试和尝试是否成功须分开。
- “无论结果如何都保存日志”：属于共有动作，不能缩进某个成功分支。

一个步骤宜有清楚的执行目的。紧密相连的动作可共处一句；拆开会增加重复条件或丢失关系时，保留复句。分支密集时可用列表或小表，但不把所有说明强制变成编号流程。

## 用观察支撑状态与恢复建议

状态说明区分已经观察到的结果、对结果的解释和仍未知的部分。退出码为零不能单独证明输出完整；产物存在不能单独证明验收通过。按任务报告必要的证据和影响，不机械输出全套状态字段。

错误提示中的恢复办法要来自已知机制、文档或验证。收到登录页可以说明本次未取得内容，但不自动证明原会话已过期；没有错误日志也不证明所有步骤成功。原因未知时明确未知，不为让错误“可行动”而编造根因、重试承诺或修复步骤。

恢复建议涉及重试、删除、再次发布等动作时，保住原有对象范围、条件和授权边界。编辑任务可以指出这些约定缺失，不能借润色建立新权限或执行这些动作。

## 简化的尺度与复核

在意思相同的情况下，用具体主体和直接动词减少解析负担。行动者未知时可以保留被动句，术语必要时可以保留专业表达。没有通用的句长、段落句数、禁词或标点配额；中文也不套英文计词阈值。已清楚的文字不为满足风格规则而重写。

先按 `editing-levels.md` 核对保真，再对确有分支或权限风险的文字做小规模情境检查：给定前提成立、失败、未知等相关情况，原文与改稿允许、要求、禁止的动作是否一致？原文未规定的行为，改稿应仍显示其未规定，而非替作者补齐。重点检查会改变行动的区别，不强制穷举所有状态。

自动检查只负责提示。正则无法证明两个近义词指向同一动作，也不能确认条件的作用域；“无告警”不证明读者会执行正确。不要为减少告警删掉条件、义务或不确定性。完整性与权限的改动要回到语义，普通文案不默认运行工具或追加多轮审查。

按用户所求交付成品或具体审阅意见。解释只保留影响使用的未决含义、必要限定或明确请求的改动理由，不自动附上模式公告和规则表。
